# Axon 配置导入时保留七天历史结果

本次升级 compare-service 及其内嵌前端，无新增数据库迁移，已部署的 Spark 作业和驱动沿用。源码包保留此前的 NULL 键 HASH 修复，但本次清理功能不需要再次替换 Spark JAR。

## 内网构建与升级

1. 解压本次源码包，使用现场原有 Maven 镜像及 BES 依赖配置构建服务。源码包已嵌入构建完成的前端，内网无需安装 Node 或重新下载前端依赖。

   ```bash
   mvn -pl compare-service -am -Pspark-3.4 -Dskip.installnodenpm=true -Dskip.npm=true clean verify
   ```

   `-Pspark-3.4` 沿用本环境的 Spark 3.4 配套版本；现场若已有其他 Maven 参数，继续沿用。生产构建使用既有 BES 配置，不使用仅用于外网测试的 `local-servlet-tests` profile。

2. 等待在途作业结束，按现有启停流程停止 bd，备份旧服务 JAR，替换 `lib/compare-service-1.0.0-SNAPSHOT.jar`。保留现场 `config/bd.env`、配置属性文件与 drivers，不用示例覆盖真实配置。
3. 启动服务，打开“核对配置 → 导入 Axon 配置”。现有确认框会明确整体替换配置和七天历史清理。上传原 Axon 脚本即可，无需修改脚本或添加 DELETE。
4. 导入完成后，页面显示截止时间及真实删除数量；任务、批次与批次项历史仍可查看。过期每日结果的详情不再可用。

## 清理口径

- 固定按结果实际 `PUBLISHED_AT` 滚动保留七天，严格早于截止时间才删除，恰等于时保留；今天重跑旧业务日期的结果保留。
- 清理每日汇总及关联差异明细、字段组合、字段差异计数，包含本次导入后已不存在的旧配置编号。
- 旧版无 `RESULT_DATE` 的明细，只有精确关联到已结束且结束时间可靠、超过七天的原任务时才删除。任务缺失、时间不明或有不可靠重复任务身份的数据保留。
- 只在管理台导入提交成功时触发；既有 `BD_DIFF_RETENTION_DAYS` 定时样本规则不变，不改任务和批次保留期限。
- 配置导入和结果清理在同一事务。解析、校验或清理失败时均回滚；提交后的缓存刷新失败不撤销清理，使用页面“重试刷新缓存”，无需重复导入。
- 删除计数来自数据库实际影响行数；不自动执行 VACUUM、缩表或其他数据库维护操作。

## 本地验证范围

本地使用仓库现有 `local-servlet-tests` profile 验证服务逻辑及事务，PostgreSQL/MySQL 方言由隔离 H2 模式回归；真实 GaussDB 集成用例需显式现场测试环境。未连接或修改生产数据库，未声称完成 BES 运行时或生产数据量压测。

源码包中的 `SOURCE-COMMIT.txt` 和 ZIP SHA-256 文件用于核对版本；内嵌前端随本次服务构建自动进入服务 JAR。
